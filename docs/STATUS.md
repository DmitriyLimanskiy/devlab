# Текущее состояние DevLab

Обновлено 31 октября 2026 года. Этот документ отражает реализацию, а не постоянные инструкции разработки.

- CLI: macOS + bash, выбор папки до запуска, PTY, чтение Git после команд и внешних изменений. Снимок сохраняется в `state.json`, правило добавляется в `.gitignore`. Добавлены каталог/выбор курса и подключение до папки; начальная сетевая версия каждого поколения — 1. Добавлены фоновая отправка последующих изменений, FIFO всех неподтверждённых состояний на диске и автоматические повторы временных сетевых ошибок.
- Backend: `GET /api/v1/catalog` читает курсы из PostgreSQL; `POST /api/v1/git-course` создаёт/возвращает активную сессию и возвращает `{ "session_id": "UUID", "generation": 0, "steps": [...] }` из PostgreSQL с фильтром курса Git и сортировкой по position. Создание браузерной сессии реализовано; POST /api/v1/cli-connect выдаёт ключ и поколение; POST /api/v1/cli-send-snapshot принимает снимки. Реализованы HTTP-чтение последнего снимка и события WebSocket после commit. Каталог и шаги курса используют асинхронные SQLAlchemy-сессии. Подготовлены модели courses/course_steps и начальная миграция Alembic; применение выполняется вручную.
- Frontend: `/catalog` — каталог, `/git-course` — страница Git; `/` переводится в каталог. Страница Git отправляет POST, показывает идентификатор сессии и шаги из БД через API (блоки text/code) и реальное состояние Git: граф коммитов/родителей, HEAD, ссылки, индекс, рабочие файлы, конфликты и операции. Добавлены восстановление связи, HTTP-сверка, время снимка и плавная подсветка изменений. Учебные материалы пока отсутствуют.
- Compose: nginx раздаёт сборку frontend, backend запускается с bind mount и reload, PostgreSQL подготовлен отдельным сервисом. Публичный локальный адрес — HTTP на loopback:8080; WebSocket проксируется через /ws/ с Upgrade и таймаутом; TLS пока не настроен.

Обновлять документ при изменении готовности компонентов; команды запуска описаны в README соответствующих частей проекта.

- Подготовлены контракт SnapshotReq/GitState, жизненный цикл в docs/practice-sessions.md и ORM-модели practice_sessions/practice_snapshots. Для новых таблиц создана миграция 8ca2ebb96c2b; хранится история снимков; миграции 20261106_0001/0002 добавляют серверный id и уникальность доставки.

- Backend разделён на api/routes (ручки), api/schemas (контракты), db/models (таблицы), db/base.py, db/config.py и db/session.py. URL API и структура таблиц при переносе сохранены.

- Проверено реальное подключение CLI → backend и подтверждение начального снимка. HTTP/PTY-проверки CLI покрывают ошибки сети и локальный режим. Проверки всех конфликтов версий/поколений backend ещё предстоят.

- Очередь повторной доставки реализована в CLI. При 401/409 отправка приостанавливается без смены поколения. Ключ в памяти, неподтверждённое тело без ключа — в пользовательском каталоге DevLab. Браузер получает снимки по HTTP и уведомления WebSocket.

- События работают в одном процессе backend. Присутствие CLI отслеживается heartbeat (10 секунд, аренда 35 секунд); интерфейс показывает статус CLI, рабочую директорию, горизонтальный цветной граф и рабочую папку → индекс. Служебные версии и время снимка скрыты. При недоступности API сохраняются последние данные.

- Frontend восстанавливает наблюдавшиеся линии из серверной истории снимков без sessionStorage. Рёбра берутся из родителей, fast-forward не создаёт merge-коммит. CLI выводит сообщения без завершающей точки и разделяет действия пустыми строками.

- CLI: снимок графа включает топологическую историю локальных веток/тегов и HEAD (до 200 коммитов), раскрытые цели тегов `ref_commits`, признаки `history_truncated`/`is_shallow` и родителей за границей `history_boundary`. Чтение работает и при unborn HEAD с другими ветками. Backend принимает новые поля в JSONB; frontend использует цели тегов и отображает признаки неполной истории. Команды не сохраняются, исторические названия восстанавливаются только из наблюдавшихся refs

- Локальный Docker Compose: frontend обслуживает отдельный Vite dev-сервер с bind mount и HMR через nginx на loopback:8080. API и WebSocket сохраняют прежние пути. Статическая сборка nginx отделена от конфигурации разработки

- `docker-compose.prod.yml` — отдельный запуск статической сборки nginx и backend без reload/bind mount; PostgreSQL доступен только во внутренней сети. TLS по-прежнему не настроен

- Проверены FIFO CLI, безопасные повторы backend, страницы истории и восстановление наблюдавшейся линии после fast-forward. Старые очереди после смены поколения сохраняются на диске без автоматической отправки. Не наблюдавшиеся CLI переходы и пересоздание репозитория по тому же пути между проверками не гарантируют полную историю

- Отправка CLI привязана к начальному чтению, завершению команд и выходу. Опрос файлов обновляет только локальный state.json; правки IDE между командами объединяются до следующей команды. Неизменившееся сетевое состояние не создаёт снимок

- Frontend: после fast-forward конечный коммит переносится на линию main/master, промежуточные коммиты dev сохраняют боковую линию. Следующий коммит main не возвращает общий tip вниз, даже если dev продолжает на него указывать
