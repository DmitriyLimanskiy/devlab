# Текущее состояние Stack Forge

CLI запускается, предлагает выбрать папку и завершает работу. Серверные контракты практики описаны в [practice-sessions.md](practice-sessions.md).
Обновлено 7 ноября 2026 года. Этот документ отражает реализацию, а не постоянные инструкции разработки.

## Вкладки Git

Верхняя часть рабочей области содержит только вкладки курсов. Отдельный tabbar, повторный заголовок курса, бейдж статуса и ссылка в каталог удалены; переход в каталог сохранён в боковом меню и бренде

Отступы Git уплотнены: внешние поля и промежуток колонок — 12 px, промежутки внутри основного блока — 8 px. Размер текста и карточек шагов сохранён, независимая прокрутка областей остаётся

Список шагов и основной блок имеют независимую прокрутку, вкладки курсов остаются на месте. На узких экранах области расположены вертикально и прокручиваются раздельно; рабочая папка и индекс перестраиваются по ширине основного блока. История графа, файлы и длинное описание шага сохраняют внутреннюю прокрутку, без переноса прокрутки на соседнюю область

Шаги отображаются слева компактными карточками с зелёным номером и заголовком. Карточки кликабельны, выбранная выделена cyan-границей и фоном. Описание выбранного шага находится полосой над репозиторием в основной области и по умолчанию свёрнуто до заголовка. Кнопка по центру полосы открывает текст и команды на всю область репозитория справа без сдвига остальных блоков. Текст прокручивается внутри; закрытие кнопкой или Escape возвращает фокус к полосе. При смене шага сохраняются раскрытие описания и размер шрифта. Отдельные кнопки скрытия и показа шагов удалены; шаги видимы и на узких экранах. У курса без шагов отображается пустое состояние

`GET /api/v1/git-course` читает из БД курсы с префиксом slug `git-`, включая песочницу и полный курс. Frontend берёт названия вкладок из title; ссылки каталога выбирают соответствующую вкладку через `?course=…`. Выбор вкладки открывает её сессию через `POST /api/v1/git-course` с JSON-телом `{"course_slug":"…"}`; slug берётся из id выбранного курса. Шаги, состояние Git и подписки относятся к выбранной сессии; смена вкладки отключает прежние браузерные подписки. Чтение списка не создаёт сессии. Записи курсов и шаги автоматически не добавляются

- Backend: `GET /api/v1/catalog` читает курсы из PostgreSQL; `POST /api/v1/git-course` создаёт/возвращает активную сессию и возвращает `{ "session_id": "UUID", "generation": 0, "steps": [...] }` из PostgreSQL с фильтром курса Git и сортировкой по position. Создание браузерной сессии реализовано; POST /api/v1/cli/connect выдаёт ключ и поколение; POST /api/v1/cli/send-snapshot принимает снимки. Реализованы HTTP-чтение последнего снимка и события WebSocket после commit. Каталог и шаги курса используют асинхронные SQLAlchemy-сессии. Подготовлены модели courses/course_steps и начальная миграция Alembic; применение выполняется вручную.
- Frontend: `/catalog` — каталог, `/git-course` — страница Git; `/` переводится в каталог. Страница Git отправляет POST, показывает шаги из БД через API (блоки text/code) и реальное состояние Git: граф коммитов/родителей, HEAD, ссылки, индекс, рабочие файлы, конфликты и операции. Добавлены восстановление связи, HTTP-сверка и плавная подсветка изменений. Учебные материалы пока отсутствуют.
- Compose: nginx проксирует Vite с HMR в разработке, backend запускается с bind mount и reload, PostgreSQL подготовлен отдельным сервисом. Публичный локальный адрес — HTTP на loopback:8080; WebSocket проксируется через /ws/ с Upgrade и таймаутом; TLS пока не настроен.

Обновлять документ при изменении готовности компонентов; команды запуска описаны в README соответствующих частей проекта.

- Подготовлены контракт SnapshotReq/GitState, жизненный цикл в docs/practice-sessions.md и ORM-модели practice_sessions/practice_snapshots. Для новых таблиц создана миграция 8ca2ebb96c2b; хранятся нормализованные текущее состояние и история графа; миграции 20261106_0001/0002 добавляют серверный id и уникальность доставки.

- Backend группирует маршруты, схемы, сервисы и модели внутри бизнес-фич в `app/api/`.



- События работают в одном процессе backend. Присутствие CLI отслеживается heartbeat (10 секунд, аренда 35 секунд); интерфейс показывает статус CLI, рабочую директорию, горизонтальный цветной граф и рабочую папку → индекс. Служебные версии и время снимка скрыты. При недоступности API сохраняются последние данные.

- Frontend восстанавливает наблюдавшиеся линии из серверной истории снимков без sessionStorage. Рёбра берутся из родителей, fast-forward не создаёт merge-коммит. CLI выводит сообщения без завершающей точки и разделяет действия пустыми строками.


- Локальный Docker Compose: frontend обслуживает отдельный Vite dev-сервер с bind mount и HMR через nginx на loopback:8080. API и WebSocket сохраняют прежние пути. Статическая сборка nginx отделена от конфигурации разработки

- `docker-compose.prod.yml` — отдельный запуск статической сборки nginx и backend без reload/bind mount; PostgreSQL доступен только во внутренней сети. TLS по-прежнему не настроен



- Frontend: после fast-forward конечный коммит переносится на линию main/master, промежуточные коммиты dev сохраняют боковую линию. Следующий коммит main не возвращает общий tip вниз, даже если dev продолжает на него указывать

- Нормализация хранения: одна запись practice_current_states на сессию, уникальные repository_commits, изменения refs в practice_graph_events и компактные practice_snapshot_receipts. Смена HEAD, файлы и индекс не создают полных исторических снимков. Frontend дочитывает историю по отдельному graph_history_id. Миграции 20261106_0003/0004 перенесли данные и удалили прежнюю practice_snapshots после проверки

- Исправлен постоянный 502 после пересоздания frontend/backend: upstream nginx используют Docker DNS и resolve с кешем 5 секунд. Проверены HTTP 200 для страниц/API и WebSocket 101 для backend и Vite HMR

- Рабочая папка и индекс переведены в отдельный оперативный канал: WS /ws/cli-worktree, HTTP-чтение и прямой JSON WebSocket без БД на обычном пути. Клиент по этому контракту отправляет только статусы файлов отдельно от FIFO графа; frontend обновляет панели независимо от истории. Первое восстановление допуска после перезапуска backend проверяет ключ через БД, последнее состояние повторяется CLI раз в 10 секунд


- Frontend: исправлены вложенные fix1 → dev → main, продвижение dev через второго родителя merge-коммита и продолжение dev после него. Раскладка различает SHA и отображения на ветках, учитывает время их появления и не создаёт ложных связей при reset/rebase. Проверены сохранённая история пользователя, 23 frontend-теста, сборка и конец графа в браузере

## Рабочая область Git

Граф занимает оставшуюся высоту правой области. Рабочая папка и индекс находятся в раскрытой по умолчанию панели «Файлы и индекс» под графом, с отдельной прокруткой списков. Записи файлов компактные: статус и путь в одной строке, длинные пути сокращаются многоточием и полностью доступны при наведении. Высота содержимого — clamp(180px, 27dvh, 240px), при вертикальном расположении файлов — clamp(210px, 34dvh, 290px)

Доступны масштаб 5–150%, возврат к 100%, вписывание и переход к HEAD. «Развернуть граф» временно скрывает шаги и файлы; «Вернуть панели» или Escape возвращают прежнюю компоновку. Оформление использует холодные полупрозрачные панели, fallback без размытия и настройки уменьшения движения/прозрачности

## Организация исходников

Backend организован по фичам `catalog`, `cli`, `courses` и `practice` внутри `app/api/`. Frontend использует `features/catalog` и `features/git`, точка входа CLI находится в `cli/src/main.py`. Общие модули frontend находятся в `shared/`. URL, сетевые форматы и схема БД сохранены.


HTTP-ручки подключения, снимков и присутствия CLI объединены под `/api/v1/cli`; backend предоставляет `/connect`, `/send-snapshot`, `/heartbeat` и `/disconnect`. `DELETE /api/v1/cli/reset-practice` очищает данные с проверкой ключа, поколения и reset_id, сохраняет ключ и увеличивает generation. В открытой bash-сессии stack-forge reset передаёт запрос основному процессу через приватный Unix-сокет, удаляет текущую очередь после подтверждения и возобновляет отправители с версии 1 без закрытия bash. Потерянный ответ можно подтвердить повтором того же reset_id без повторного сброса. Браузер автоматически перечитывает историю при смене поколения. Внешний stack-forge reset сохраняет отдельный режим выбора курса с новым подключением. Доступна справка stack-forge --help. Оперативные HTTP/WebSocket-адреса файлов остаются прежними.

## Содержание шагов Git

В БД полный курс содержит 53 занятия по 154 командам каталога, песочница — 3 вводных шага. Описания обоих курсов хранятся в `content.markdown` и отображаются frontend как Markdown с заголовками, абзацами, списками, ссылками и блоками команд. Ранее использовавшиеся блоки text/code читаются для совместимости. Учебные материалы не хранятся в backend-исходниках; статусы прохождения шагов пока не добавлены

При раскрытии текста шага вкладки и список шагов остаются доступны. Основной размер текста — 16 px, кнопки А− / А+ позволяют менять его от 14 до 24 px

Состояние интерфейса сохраняется в памяти открытой страницы отдельно для каждой практической сессии: выбранный шаг, раскрытие инструкции и графа, размер текста, раскрытие файлов, масштаб и вписывание графа, прокрутка шагов, инструкций, графа и файлов. Переключение вкладок не сбрасывает эти настройки. После перезагрузки страницы применяются начальные настройки; снимки и история Git по-прежнему получаются с backend
