# DevLab Backend

Актуализировано 30 октября 2026 года. Применять вместе с корневым `AGENTS.md`. Здесь закреплены серверная зона и текущий API; продуктовые решения находятся в корне.

## Структура и ответственность

- Python 3.13, FastAPI, Pydantic, Uvicorn; зависимости в `requirements.txt`.
- `app/schemas/` — SQLAlchemy-модели таблиц и общая metadata; `alembic/` — версии схемы. Не путать их с Pydantic-моделями HTTP.
- `app/main.py` — создание FastAPI и подключение роутеров.
- `app/routes/courses/` — маршруты каталога и направлений; `app/models/courses/` — модели запросов/ответов. Pydantic-модели не считать таблицами базы данных.
- Роутер подключать после объявления его обработчиков. Не создавать одинаковые method/path в нескольких местах.
- Сервер отвечает за API, будущие сессии и хранение снимков, но не запускает Git и пользовательские команды.

## Контракты API

- API располагается под `/api/v1`; frontend использует отдельные браузерные маршруты. Имена Python-папок не определяют URL.
- Описывать форму запросов и ответов моделями, согласовывать изменения с потребителями API.
- Список действующих маршрутов и степень их готовности хранить в документации API и `../docs/STATUS.md`.
- При замене временной реализации сохранять контракт либо явно обновлять все стороны. Не считать наличие обработчика доказательством готовности всей функции.

## Будущая синхронизация

Следовать однопользовательскому сценарию в корневом AGENTS. Точные новые URL и модели согласовать при задаче, не выдавать обсуждавшиеся примеры за реализованный контракт.

- Валидировать входные данные и версию схемы, ограничивать объём снимка.
- Отделять транспортные модели, работу с базой и жизненный цикл сессии от обработчиков.
- Подтверждать доставку после сохранения; повторная доставка безопасна, устаревшая версия не заменяет новую.
- Различать сессию, поколение подключения и версию снимка. Перезапуск CLI и пересоздание локального файла не должны приводить к конфликту версий.
- PostgreSQL / JSONB — согласованное целевое хранилище, модели описываются SQLAlchemy 2, изменения структуры — Alembic. Не применять миграции и не вызывать create_all при старте API. Применённые ревизии не редактировать.
- События браузеру поступают от FastAPI; последняя версия восстанавливается через HTTP. Несколько процессов потребуют решения для межпроцессной доставки.

## Разработка и проверки

В режиме разработки допустимы bind mount исходников и Uvicorn `--reload`. В production использовать собранный образ без reload. При изменении зависимостей пересобирать образ. Проверять, что healthcheck обращается к действующему маршруту, а порты и адреса соответствуют выбранному режиму запуска.

Без Docker из `backend/`: установить `requirements.txt` в отдельное окружение и запустить `uvicorn app.main:app --reload`.

При изменении маршрута проверять регистрацию в приложении, HTTP-код и форму ответа, а также обращения в `frontend/src/routes.js`. При реализации синхронизации дополнительно проверять повторные запросы, устаревшие версии, новое подключение и сбои сохранения. Не подключать PostgreSQL и не выбирать дополнительные зависимости для задачи, которой это не требуется.

Подключение задавать через окружение, без секретов в исходниках и alembic.ini. SQL миграции должен быть воспроизводимым и не зависеть от импорта актуальных ORM-моделей. Команды и детали таблиц — в README.md.
