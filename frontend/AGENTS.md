# DevLab Frontend

Актуализировано 30 октября 2026 года. Применять вместе с корневым `AGENTS.md`. Подробная дизайн-система — `DESIGN.md`; не менять её направление отдельно от согласованной компоновки.

## Структура и маршруты

React 19 + Vite, JavaScript/JSX, Lucide. `src/main.jsx` — оболочка приложения, каталог и обработка маршрутов/запросов; `src/GitCourse.jsx` — страница Git; `src/ui.jsx` — общие компоненты; `src/tokens.css` — токены; `src/styles.css` — стили. Не добавлять UI-фреймворк или роутер без необходимости задачи.

Браузерные страницы и JSON API имеют отдельные адреса. Все адреса централизованы в `src/routes.js`; синхронно обновлять их при изменении backend. Действующие маршруты описывать в README и `../docs/STATUS.md`, не дублировать их список здесь.

Каталог показывает данные API и переходы к реализованным страницам направлений. Сохранять состояния загрузки, ошибки с повтором, пустого списка и неизвестного пути. Отменять запросы при размонтировании через AbortController. Не возвращать удалённые маршруты без отдельной задачи.

## Согласованная компоновка

- Общая оболочка напоминает редактор: верхняя панель бренда, боковое меню, вкладка, рабочая область. Боковое меню остаётся, может сворачиваться; активная страница обозначена.
- Каталог использует всю ширину рабочей области под адаптивную сетку компактных карточек: обычная минимальная ширина 280 px, максимальная 380 px, на узких экранах карточка сужается до доступной ширины. Единственную карточку не растягивать на всю строку. Страница Git занимает почти всю доступную ширину и высоту рабочей области без центрального ограничения max-width.
- Внутри страницы Git слева вертикальная колонка шагов: запуск `devlab`, выбор папки, работа в bash; затем пояснение `state.json` и выход из CLI.
- Справа — единая область репозитория: строка состояния, терминальный блок, история, индекс, рабочая папка. Панели расположены строго друг под другом.
- Не заменять эту структуру горизонтальной инструкцией сверху и графом слева от индекса/файлов: пользователь предпочёл прежний вертикальный порядок.
- История получает немного больше высоты. Левую колонку и правую область выравнивать по общей доступной высоте, оставляя небольшие внешние поля.
- Интерфейс немного увеличен: заголовок курса 28 px, заголовки панелей 15 px, шаги 14 px, описания панелей 13 px. Не увеличивать всё пропорциональным масштабированием.
- На узких экранах колонки переходят в одну, контент доступен прокруткой. Изменения страницы курса не должны растягивать каталог или ломать меню.

## Визуальный язык

Референс: `../sources/Изображение ChatGPT 28 окт. 2026 г., 19_15_36.jpg`. Сохранять почти чёрный фон, холодные тонкие рамки, cyan-акцент, зелёные круглые номера шагов, оранжевые технические акценты, моноширинные команды и служебные подписи. Использовать существующие токены и компоненты, дополнять их при необходимости. Не переносить элементы социальной сети с изображения.

Состояние подключения обозначать текстом, не одним цветом. Зелёные номера шагов не означают успешное подключение. Сохранять видимый клавиатурный фокус, доступные названия кнопок и иерархию заголовков.

## Достоверность интерфейса

Отображать только доступные возможности. Демоданные явно обозначать; не выдавать их за живое состояние репозитория. При отсутствии данных показывать понятное пустое состояние. Не представлять поясняющий терминальный блок как исполняемый терминал.

Визуализацию строить из нормализованного снимка backend, не вычислять семантику команд заново. Подключение новых функций выполнять в рамках соответствующей задачи.

## Запуск и проверки

Из `frontend/`: `npm ci`, `npm run dev`; проверка production-сборки — `npm run build`. Локальный Vite проксирует `/api/` на `127.0.0.1:8000`; backend должен быть доступен по этому адресу. В Docker статику раздаёт nginx; обновление сборки — `docker compose up -d --build nginx` из корня.

После изменений интерфейса проверять сборку, страницы и переходы, раскрытое/свёрнутое меню, узкий экран и отсутствие горизонтального переполнения. Для изменений компоновки визуально сверять результат с согласованной структурой и референсом. Указывать фактические проверки; не заявлять проверку браузером по одной успешной сборке.
