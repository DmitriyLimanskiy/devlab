# DevLab Frontend

Актуализировано 30 октября 2026 года. Применять вместе с корневым `AGENTS.md`. Подробная дизайн-система — `DESIGN.md`; не менять её направление отдельно от согласованной компоновки.

## Структура и маршруты

React 19 + Vite, JavaScript/JSX, Lucide. `src/main.jsx` — оболочка приложения, каталог и обработка маршрутов/запросов; `src/catalog/` — данные каталога; `src/courses/git/` — страница и шаги курса; `src/practice/git/` — граф, состояние практики и подписки; `src/courses/git/GitCourse.jsx` — страница Git; `src/shared/ui.jsx` — общие компоненты; `src/tokens.css` — токены; `src/styles.css` — стили. Не добавлять UI-фреймворк или роутер без необходимости задачи.

Браузерные страницы и JSON API имеют отдельные адреса. Все адреса централизованы в `src/routes.js`; синхронно обновлять их при изменении backend. Действующие маршруты описывать в README и `../docs/STATUS.md`, не дублировать их список здесь.

Страница Git содержит вкладки песочницы и полного курса, полученные из API. Выбранный slug хранить в URL; сессию открывать только для выбранного курса. При смене вкладки очищать прежнее состояние и подписки, не смешивать граф, файлы и шаги разных сессий. Название, статус и шаги брать из API; пустые шаги показывать явно

Каталог показывает данные API и переходы к реализованным страницам направлений. Сохранять состояния загрузки, ошибки с повтором, пустого списка и неизвестного пути. Отменять запросы при размонтировании через AbortController. Не возвращать удалённые маршруты без отдельной задачи.

## Согласованная компоновка

- Общая оболочка напоминает редактор: верхняя панель бренда, боковое меню и рабочая область. Отдельный tabbar с названием раздела отсутствует. На странице Git сверху только вкладки курсов, без повторного заголовка курса, бейджа и ссылки в каталог. Переход в каталог доступен через боковое меню и бренд. Боковое меню остаётся, может сворачиваться; активная страница обозначена. На экранах до 480 px меню изначально свёрнуто, раскрывается прежней кнопкой.
- Компоновка Git плотная: внешние поля и промежуток колонок — 12 px, промежутки внутри основного блока — 8 px, внутренние поля панелей — 12 px. Не уменьшать текст и кликабельные карточки ради экономии места
- Каталог использует всю ширину рабочей области под адаптивную сетку компактных карточек: обычная минимальная ширина 280 px, максимальная 380 px, на узких экранах карточка сужается до доступной ширины. Единственную карточку не растягивать на всю строку. Страница Git занимает почти всю доступную ширину и высоту рабочей области без центрального ограничения max-width.
- Внутри страницы Git слева компактная колонка кликабельных карточек шагов: зелёный круглый номер и заголовок, выбранный шаг выделен cyan-границей и фоном. Описание и команды выбранного шага показывать справа над строкой «Репозиторий». Поле описания имеет постоянную высоту при переключении шагов; длинный текст раскрывается отдельной кнопкой с плавным изменением высоты и внутренней прокруткой. Учитывать prefers-reduced-motion. Под списком — выход из CLI. Технические поколения, версии и служебные пояснения не показывать в основном интерфейсе.
- Справа — единая область репозитория: строка состояния CLI, рабочая директория и горизонтальная история. Под историей — рабочая папка слева и индекс справа с одиночным шевроном между ними, направленным к индексу.
- Шаги остаются слева. Граф показывает старые коммиты слева, новые справа, разветвления и слияния на отдельных цветных линиях. Main сохраняет cyan-цвет. Не изображать разветвление, которого нет в DAG.
- История получает немного больше высоты. Левую колонку и правую область выравнивать по общей доступной высоте, оставляя небольшие внешние поля.
- Размеры интерфейса: заголовки панелей 15 px, шаги 14 px, описания панелей 13 px. Не увеличивать всё пропорциональным масштабированием.
- Список шагов и основной блок прокручиваются независимо в пределах доступной высоты; вкладки курсов остаются на месте. Содержимое не выходит за рамки панелей. На узких экранах колонки переходят в одну, каждая область сохраняет собственную прокрутку. Панели рабочей папки и индекса складывать по доступной ширине основного блока. Изменения страницы курса не должны растягивать каталог или ломать меню.

## Визуальный язык

Референс: `../sources/Изображение ChatGPT 28 окт. 2026 г., 19_15_36.jpg`. Сохранять почти чёрный фон, холодные тонкие рамки, cyan-акцент, зелёные круглые номера шагов, оранжевые технические акценты, моноширинные команды и служебные подписи. Использовать существующие токены и компоненты, дополнять их при необходимости. Не переносить элементы социальной сети с изображения.

Состояние подключения обозначать текстом, не одним цветом. Зелёные номера шагов не означают успешное подключение. Сохранять видимый клавиатурный фокус, доступные названия кнопок и иерархию заголовков.

## Достоверность интерфейса

Отображать только доступные возможности. Демоданные явно обозначать; не выдавать их за живое состояние репозитория. При отсутствии данных показывать понятное пустое состояние. Не представлять поясняющий терминальный блок как исполняемый терминал.

Визуализацию строить из нормализованного снимка backend, не вычислять семантику команд заново. Подключение новых функций выполнять в рамках соответствующей задачи.

## Запуск и проверки

Из `frontend/`: `npm ci`, `npm run dev`; проверка production-сборки — `npm run build`. Локальный Vite проксирует `/api/` на `127.0.0.1:8000`; backend должен быть доступен по этому адресу. В локальном Docker Compose frontend обслуживает Vite с HMR и bind mount исходников; nginx проксирует frontend, API и WebSocket на едином адресе. Не заменять этот режим раздачей статической сборки при разработке. Production-сборка и конфигурация статического nginx остаются отдельными файлами.

После изменений интерфейса проверять сборку, страницы и переходы, раскрытое/свёрнутое меню, узкий экран и отсутствие горизонтального переполнения. Для изменений компоновки визуально сверять результат с согласованной структурой и референсом. Указывать фактические проверки; не заявлять проверку браузером по одной успешной сборке.

При фоновых обновлениях сохранять последние данные и стабильные ключи строк. Сравнивать поколение и версию, восстанавливать снимок после подписки и переподключения. Статус WebSocket не выдавать за присутствие CLI. Анимации данных соблюдать по DESIGN.md, включая prefers-reduced-motion.

В конце отдельных UI-предложений и абзацев не ставить точку; внутреннюю пунктуацию и код сохранять. Присутствие CLI показывать только по действующему серверному heartbeat, зелёным цветом и текстом «CLI подключен».

Строить раскладку графа последовательным воспроизведением серверной истории снимков без sessionStorage/localStorage. Одинаковая история даёт одинаковые линии после перезагрузки. Текущие refs и HEAD брать из последнего снимка, наблюдавшиеся названия отличать подписью «история». Коммиты вне текущего снимка обозначать как историю наблюдений. Не создавать отсутствующие связи родителей и merge-коммиты при fast-forward. Смену папки и наблюдавшееся отсутствие репозитория использовать как границу истории; одного пути недостаточно для безусловной идентификации пересозданного репозитория. Историю загружать страницами до graph_history_id из ответа текущего состояния, затем дочитывать новые события. ID доставки снимка не является курсором истории. Исторические кадры содержат только впервые появившиеся коммиты, refs восстанавливает backend; накопление коммитов выполняется при воспроизведении. Annotated tags привязывать по ref_commits, обозначать обрезку и shallow-историю

При продвижении ветки на коммит другой линии сохранять исходное отображение SHA и добавлять отображение на именованной линии принимающей ветки. Связь предков проверять по всем родителям. Продолжение ветки соединять с её отображением родителя, учитывая время появления: поздние отображения после reset не меняют старые рёбра. При reset/rebase не добавлять связь со старой вершиной, если она не предок новой. Не допускать наложения узлов одной линии. При вложенных слияниях выбирать ближайшее подходящее отображение родителя, не только исходный SHA

Рабочую папку и индекс получать отдельным useWorktree независимо от usePracticeState и загрузки истории графа. WebSocket оперативного канала содержит сами данные файлов; HTTP нужен при открытии, переподключении и сверке. Не подставлять файлы из снимка БД. При отсутствии оперативных данных показывать ожидание, при ошибке сохранять последние данные с пояснением. Версии оперативного канала не сравнивать с версиями графа
