# Stack Forge Frontend

Актуализировано 7 ноября 2026 года. Применять вместе с корневым `AGENTS.md`. Подробная дизайн-система — `DESIGN.md`; не менять её направление отдельно от согласованной компоновки.

## Структура и маршруты

React 19 + Vite, JavaScript/JSX, Lucide. `src/main.jsx` — оболочка и выбор страницы. Код каталога находится в `src/features/catalog/`, страница Git, шаги, граф и подписки — в `src/features/git/`. Общие UI-компоненты, запросы и маршруты находятся в `src/shared/`. Токены и общие стили остаются в `src/tokens.css` и `src/styles.css`. Не добавлять UI-фреймворк или роутер без необходимости задачи.

Браузерные страницы и JSON API имеют отдельные адреса. Все адреса централизованы в `src/shared/routes.js`; синхронно обновлять их при изменении backend. Действующие маршруты описывать в README и `../docs/STATUS.md`, не дублировать их список здесь.

Страница Git показывает вкладки курсов с префиксом `git-` из защищённого API каталога. Выбранный slug хранить в URL. Показывать название, описание и статус курса.

Каталог показывает данные API и переходы к реализованным страницам направлений. Сохранять состояния загрузки, ошибки с повтором, пустого списка и неизвестного пути. Сообщение об ошибке загрузки и кнопку повтора размещать в отдельной панели по центру соответствующей области данных. Отменять запросы при размонтировании через AbortController. Не возвращать удалённые маршруты без отдельной задачи.

Каталог при ответе `401` показывает форму входа с переходом к регистрации. После регистрации форма возвращается ко входу с заполненной почтой. После входа каталог повторяет запрос с браузерной cookie. При открытии `/` приложение заменяет адрес на `/catalog`.

## Согласованная компоновка

- Общая оболочка напоминает редактор: верхняя панель бренда, боковое меню и рабочая область. Отдельный tabbar с названием раздела отсутствует. Переход в каталог доступен через боковое меню и бренд. Боковое меню остаётся, может сворачиваться; активная страница обозначена. На экранах до 480 px меню изначально свёрнуто, раскрывается прежней кнопкой.
- Каталог использует всю ширину рабочей области под адаптивную сетку компактных карточек: обычная минимальная ширина 280 px, максимальная 380 px, на узких экранах карточка сужается до доступной ширины. Единственную карточку не растягивать на всю строку. Страница Git занимает почти всю доступную ширину и высоту рабочей области без центрального ограничения max-width.

## Достоверность интерфейса

Отображать только доступные возможности. Демоданные явно обозначать; не выдавать их за живое состояние репозитория. При отсутствии данных показывать понятное пустое состояние. Не представлять поясняющий терминальный блок как исполняемый терминал.


## Запуск и проверки

Из `frontend/`: `npm ci`, `npm run dev`; проверка production-сборки — `npm run build`. Локальный Vite проксирует `/api/` на `127.0.0.1:8000`; backend должен быть доступен по этому адресу. В локальном Docker Compose frontend обслуживает Vite с HMR и bind mount исходников; nginx проксирует frontend, API и WebSocket на едином адресе. Не заменять этот режим раздачей статической сборки при разработке. Production-сборка и конфигурация статического nginx остаются отдельными файлами.

После изменений интерфейса проверять сборку, страницы и переходы, раскрытое/свёрнутое меню, узкий экран и отсутствие горизонтального переполнения. Для изменений компоновки визуально сверять результат с согласованной структурой и референсом. Указывать фактические проверки; не заявлять проверку браузером по одной успешной сборке.


В конце отдельных UI-предложений и абзацев не ставить точку; внутреннюю пунктуацию и код сохранять.
