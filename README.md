# DevLab

Базовый шаблон DevLab — сервиса курсов по разным технологиям.

## Сборка без запуска

Нужен Docker с Compose:

```sh
cp .env.example .env
docker compose build
```

Команда только собирает образы backend и frontend (Vite), контейнеры не запускает. PostgreSQL использует готовый образ `postgres:17-alpine`.

## Запуск вручную

После сборки применить образы и запустить приложение: `docker compose up -d --force-recreate`. Пересборка сама по себе не обновляет уже работающие контейнеры.

Главная страница: http://localhost:8080. Frontend: `/catalog` — каталог курсов, `/` переводит на `/catalog`; неизвестные пути показывают страницу 404. Backend: `GET /api/v1/catalog`. Каталог получает данные из API. Каталог читает записи PostgreSQL; статус planned отображается как «В разработке». Автоматические API docs отключены.

```sh
curl http://localhost:8080/api/v1/catalog
docker compose ps
docker compose logs -f
```

В локальном Compose frontend обслуживает Vite с HMR: изменения в `frontend/` сразу поступают в браузер без пересборки. Nginx проксирует frontend, `/api/` и `/ws/`. После изменения конфигурации выполните `docker compose up -d --build`; после изменения frontend-зависимостей перезапустите `docker compose restart frontend` — при старте выполняется `npm ci`. Исходники подключены через bind mount, зависимости хранятся в отдельном volume. `nginx/Dockerfile` и `nginx/default.conf` используются отдельной production-конфигурацией. Backend доступен только во внутренней сети; PostgreSQL публикует порт 5432 только на loopback для локальной разработки. Локальная конфигурация использует HTTP и доступна только на loopback; WebSocket проксируется через /ws/; домен и TLS пока не настроены.

## Production-сборка

Отдельная конфигурация со статикой nginx и backend без reload и bind mount исходников:

```sh
docker compose -f docker-compose.prod.yml up -d --build --remove-orphans
```

Возврат к разработке с HMR:

```sh
docker compose up -d --build --remove-orphans
```

Конфигурации используют одно имя проекта и один volume PostgreSQL: это переключение режима того же приложения, а не параллельные окружения. При переключении в production удаляется только контейнер Vite; данные и volume зависимостей сохраняются. Порт PostgreSQL в production не публикуется. Публичный вход пока остаётся HTTP на loopback:8080; для внешнего развёртывания нужно отдельно настроить TLS и домен.

## PostgreSQL

Данные хранятся в именованном Docker volume `devlab_postgres_data`. Перезапуск контейнера, пересборка и `docker compose down` сохраняют данные. `docker compose down -v` удаляет volume вместе с данными — не используйте эту команду, если данные нужны. Volume не заменяет резервную копию.

База подготовлена как отдельный сервис. Модели таблиц курсов и шагов, а также миграции Alembic подготовлены в backend (см. [backend/README.md](backend/README.md)); применять миграции нужно вручную. Каталог использует асинхронные SQLAlchemy-сессии; для него требуются применённая миграция и корректные параметры подключения. Сессии и постоянная фоновая доставка из CLI реализованы; браузер получает последний снимок по HTTP и обновляется по событиям WebSocket. В `cli/` есть первая локальная версия CLI с интерактивным bash; установка и запуск описаны в [cli/README.md](cli/README.md).

## Разработка без Docker

Backend (Python 3.13):

```sh
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload
```

Frontend (Node.js 22):

```sh
cd frontend
npm ci
npm run dev
```

Vite проксирует `/api/` на localhost:8000. Production-сборка: `npm run build`. Описание дизайн-системы — `frontend/DESIGN.md`, токены — `frontend/src/tokens.css`.

## Адреса

| Режим | Главная | Курсы | API |
| --- | --- | --- | --- |
| Docker / nginx | http://localhost:8080/ | http://localhost:8080/catalog | http://localhost:8080/api/v1/ |
| Vite dev | http://localhost:5173/ | http://localhost:5173/catalog | http://localhost:5173/api/v1/ |
| Vite preview | http://localhost:4173/ | http://localhost:4173/catalog | http://localhost:4173/api/v1/ |

Для Vite dev и preview отдельно запустите backend на порту 8000. Порт 8000 обслуживает JSON API, а не HTML-страницы. Прокси nginx и Vite сохраняют `/api/v1/` в запросах. Адреса frontend собраны в `frontend/src/routes.js`; backend использует APIRouter с префиксом `/api/v1`.

Страница Git: `/git-course`, переход «Открыть» в каталоге. Список вкладок «Песочница» и «Полный курс» запрашивается через `GET /api/v1/git-course` (slug `git-sandbox` и `git-full-course`). Выбранная вкладка отправляет `POST /api/v1/git-course` с JSON-телом `{"course_slug":"…"}`; ручка создаёт/возвращает отдельную активную сессию курса и возвращает session_id, generation и его шаги из PostgreSQL в поле steps. Выбор сохраняется в URL через `?course=…`. Frontend отображает шаги из API: текстовые блоки и команды; для пустого полного курса показывает ожидание материалов. CLI подключается и передаёт начальный и изменившиеся снимки; браузер отображает реальный граф коммитов, HEAD, ветки, индекс, рабочие файлы, конфликты и незавершённые операции.

Структура backend: HTTP-маршруты — `backend/app/api/routes`, Pydantic-контракты — `backend/app/api/schemas`, SQLAlchemy-таблицы — `backend/app/db/models`. Подробная карта файлов и API — в [backend/README.md](backend/README.md).

CLI получает курсы и подключается к активной сессии до выбора папки, в фоне отправляет начальный и последующие изменившиеся снимки с очередью и повторными попытками. Настройки сервера, локальный режим и текущие ограничения — в [cli/README.md](cli/README.md).

### Обновление состояния в браузере

После открытия Git браузер подключает `/ws/practice-sessions/{session_id}` и читает `/api/v1/practice-sessions/{session_id}/snapshot`. Сигнал после commit вызывает повторное чтение. При разрыве соединения последнее состояние остаётся на экране, WebSocket переподключается; HTTP дополнительно сверяется каждые 10 секунд. Версии сравниваются вместе с поколением. Присутствие CLI подтверждается отдельным heartbeat каждые 10 секунд с арендой 35 секунд.

Граф показывает до лимита коммитов снимка, связи родителей, ссылки и HEAD. Annotated tags привязываются к коммитам через `ref_commits`; ссылки на объекты вне истории перечисляются отдельно. Обрезанная и shallow-история обозначаются под графом. Содержимое файлов, diff и сообщения коммитов не передаются. Плавные изменения и режим уменьшенного движения закреплены в `frontend/DESIGN.md`. Frontend-проверки: `node --test frontend/src/practice/git/practiceState.test.js` и `npm --prefix frontend run build`.

Раскладка графа восстанавливается по серверной истории снимков, без браузерного хранилища. Основная линия следует первым родителям, боковые линии слияний — остальным. После перезагрузки одинаковая история даёт одинаковый граф. Fast-forward не создаёт merge-коммит, но сохраняет ранее наблюдавшуюся боковую линию. Backend обновляет одну запись текущего состояния, хранит коммиты однократно и добавляет только изменения refs/новые коммиты в историю графа. Простое переключение ветки обновляет HEAD без новой записи графа. Исторические названия отличаются от действующих refs; коммиты вне текущего снимка отмечены как история наблюдений. CLI доставляет все наблюдавшиеся состояния по порядку. Потерянные до записи наблюдения не восстанавливаются.

Nginx обновляет адреса backend и Vite через Docker DNS (`127.0.0.11`, кеш 5 секунд). После пересоздания контейнеров новые IP подхватываются без перезапуска Nginx. При пересоздании возможен короткий перерыв до готовности сервиса и обновления DNS

### Оперативные файлы и индекс

CLI отдельно отправляет по `WS /ws/cli-worktree` с `{session_id, generation, version, state}`. В state только kind/path/files: статусы индекса и рабочей папки, конфликты и пути переименований, без содержимого файлов, diff и графа. Наблюдатель обновляет state.json при командах и внешних изменениях; отдельный поток проверяет файл каждые 0,3 секунды и отправляет обновлённые статусы без ожидания команды. Неизменившиеся данные не создают новую версию.

Backend хранит последнее состояние в памяти одного процесса. Браузер читает `/api/v1/practice-sessions/{id}/worktree` и получает сами данные по `/ws/practice-sessions/{id}/worktree`, независимо от истории графа и её доступности. При перезагрузке backend CLI повторно присылает последнее состояние в пределах 10 секунд. Ключ кешируется при подключении; после сброса памяти его первая проверка требует БД. Оперативные файлы не записываются в PostgreSQL, в снимках графа files пустой.

### Рабочая область Git и сброс практики

Список шагов расположен слева, на узком экране — над репозиторием. Описание выбранного шага находится полосой в основной области над репозиторием, по умолчанию свёрнуто и раскрывается кнопкой по центру полосы. Отдельных кнопок скрытия и показа шагов нет. Граф занимает оставшуюся высоту справа; под ним раскрыта панель «Файлы и индекс» с независимой прокруткой списков. Доступны масштаб, вписывание, переход к HEAD и разворачивание графа со скрытием соседних панелей; Escape возвращает обычный вид.

Команда `devlab reset` внутри открытой bash-сессии очищает серверную историю практики и текущую очередь доставки после подтверждения, сохраняя оболочку и локальный репозиторий. Новое поколение начинает доставку с версии 1; браузер автоматически перечитывает историю. Повтор того же запроса безопасен при потере ответа. Вызов вне этой оболочки выбирает курс и создаёт отдельное подключение; подробности — в [cli/README.md](cli/README.md) и [docs/practice-sessions.md](docs/practice-sessions.md).
