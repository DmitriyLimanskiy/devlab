# Работа над DevLab CLI

Актуализировано 30 октября 2026 года. Применять также инструкции корневого `AGENTS.md`. Документацию и пояснения писать по-русски.

## Архитектура и согласованное поведение

- Самостоятельный Python-пакет с `src/` и точкой входа `devlab` в `pyproject.toml`.
- Первая платформа — macOS, первая оболочка — bash из `PATH`, Python 3.11+.
- `main.py` отвечает за запуск и оформление; `terminal.py` — за PTY и жизненный цикл bash.
- Выбор курса и подключение к активной браузерной сессии происходят до выбора папки; выбор папки — до запуска bash; по умолчанию предлагать папку запуска CLI и подтверждать её нажатием Enter; подсказка управления `exit` / `Ctrl+D`.
- Используется временный rc-файл; пользовательские конфигурации и история на диске не меняются.
- `git_state.py` читает нормализованный Git-снимок, `observer.py` объединяет сигналы bash и опрос файлов. `state.json` сохраняется в выбранной папке после выхода; сетевой транспорт отделять от наблюдения и терминала. Сам файл исключается из снимка и Git-наблюдения; оперативный WebSocket-отправитель читает его отдельно. Перед запуском bash `.gitignore` в выбранной папке создаётся или дополняется правилом `state.json`; сохранять существующее содержимое и не дублировать действующее явное правило. Символические ссылки не изменять. Если state.json существует, спрашивать yes/no: yes — обновить сразу, no — сохранить до следующего изменения Git относительно начала сессии. Не перезаписывать символическую ссылку или каталог.

## Правила изменений

- Не заменять bash собственным разбором команд или последовательностью вызовов `subprocess`.
- Сохранять настоящую интерактивную сессию, коды завершения, передачу размеров окна и восстановление терминала.
- PTY передаёт байты и не определяет завершение команд. Сигнал завершения передаётся через PROMPT_COMMAND и отдельный pipe.
- Чтение Git, наблюдение и синхронизацию выделять из терминального транспорта.
- Не подключать backend и не расширять продуктовые функции без соответствующей задачи.
- Не обещать поддержку других ОС, оболочек и версий без проверки.
- Не менять пользовательские shell/Git-настройки и не сохранять команды или вывод без согласованной функции.

## Проверки

Из `cli/`: `python3 -m unittest discover -s tests -v`.
Использовать реальный bash в PTY для проверки терминального поведения. При изменении транспорта проверять выход, `Ctrl+C`, изменение размера и восстановление терминала. Git проверять на реальных временных репозиториях: пустой, detached HEAD, индекс, конфликт, внешние изменения и отсутствие лишних версий. Полноэкранные программы дополнительно проверять вручную.

Сетевой транспорт держать в api.py, диалог подключения — в connection.py. Ключ хранить только в памяти Python, не логировать и не экспортировать в bash/файлы. Для локальных сценариев сохранять DEVLAB_OFFLINE=1. Сетевые версии нового поколения не продолжать из локального state.json. Не повторять cli/connect автоматически: повтор меняет поколение. Сбои сети не должны запрещать локальную работу.

Фоновую доставку держать в sync.py. Запускать её поток после fork PTY. Наблюдатель передаёт состояние напрямую; не наблюдать за state.json ради доставки истории графа. Повторы используют неизменные generation/version; запоздалое подтверждение не удаляет более новый снимок. Хранить FIFO всех неподтверждённых снимков, удалять только подтверждённую голову очереди. На диск сохранять тела неподтверждённых запросов, без ключа, вне пользовательского репозитория по умолчанию. Ошибки авторизации/конфликта не должны запускать автоматический cli/connect. Новое поколение отправляет заново прочитанное состояние с версии 1; старую очередь не воспроизводить с новым ключом.

Присутствие CLI держать в отдельном presence.py, независимо от снимков. Поток запускать после fork PTY, ошибки не блокируют оболочку. Heartbeat не увеличивает версию снимка и не меняет поколение. При выходе отправлять отключение с ограниченным ожиданием; при недействующем ключе не переподключаться автоматически.

При подключении выводить только название курса без UUID и поколения. Не выводить служебные сообщения о пути state.json, сохранении прежнего снимка и фоновой синхронизации. При штатном завершении после «Сессия DevLab завершена» выводить «Хорошего дня».

В сообщениях CLI, комментариях и docstrings не ставить завершающие точки. Между этапами диалога и перед следующим приглашением bash оставлять пустую строку, не меняя вывод Git и других пользовательских программ.

Граф снимка строить из достижимых коммитов локальных веток, тегов на коммиты и HEAD, включая случай unborn HEAD при наличии других refs. Сохранять порядок родителей и топологический порядок коммитов, явно обозначать лимит истории и shallow-репозиторий. Исходные объекты refs и целевые коммиты тегов хранить раздельно. Не восстанавливать названия удалённых веток из структуры коммитов

Очереди прошлых поколений не удалять при новом подключении и не отправлять с новым ключом; сообщать об оставшихся очередях. История гарантируется для наблюдавшихся состояний в рамках действующего подключения, автоматическое восстановление старого поколения не предусмотрено

Опрос файлов и периодическая сверка обновляют локальный state.json без постановки снимка в очередь графа. Отправлять начальный снимок, изменившееся состояние после завершения команды и финальное состояние при выходе. Если опрос уже обновил локальный снимок, следующая команда всё равно должна передать это состояние отправителю; неизменившееся сетевое состояние не создаёт версии. Ошибка чтения после команды сохраняет необходимость отправки до успешной повторной проверки

Оперативную доставку файлов и индекса держать в worktree.py отдельным потоком после fork PTY. Отправлять только kind/path/files по постоянному WebSocket после начального чтения и при изменениях state.json, независимо от FIFO графа и завершения команд. Здесь достаточно последнего неподтверждённого состояния; на диск и в БД его не архивировать. Повтор последней версии восстанавливает память backend после перезапуска. В исторические снимки для БД передавать files=[], не создавая сетевую версию графа только из-за изменения файлов или индекса

Оперативный отправитель проверяет state.json каждые 0,3 секунды, использует атомарно записанный файл текущего запуска и игнорирует устаревший/недописанный JSON. При no на перезапись старого файла отправлять свежее начальное чтение, а не старый файл. Переподключение WebSocket повторяет только последнее состояние; ключ передавать заголовком, не URL. Использовать библиотеку websockets, не собственный WebSocket-протокол

## Структура пакета

`main.py` и `__main__.py` — точки входа. `cli/` — API, выбор подключения и присутствие; `practice/` — чтение Git, локальное наблюдение, подготовка папки и доставка состояния; `shell/` — PTY и bash. Импорты между областями выполнять через devlab; не зависеть от Python-пакетов backend


Команды `devlab reset` и `devlab --help` обрабатывать в классе CliCommands до подготовки PTY. Справка не требует сети или TTY. Внутри bash reset делегируется основному CLI через приватный Unix-сокет: ключ остаётся в памяти основного процесса, окружение содержит лишь DEVLAB_CONTROL_SOCKET. Остановить и дождаться отправителей, получить новое поколение без замены ключа и только после подтверждения удалить очередь остановленного поколения. Прочитать свежий Git и возобновить отправители с версии 1 без закрытия bash. При неопределённом ответе сохранить reset_id и приостановить доставку до повторного reset, не выполнять cli/connect автоматически. Очереди прочих поколений сохранять. Вне открытого CLI сброс выбирает курс и создаёт отдельное подключение, отзывающее прежний ключ. В DEVLAB_OFFLINE=1 сброс недоступен
