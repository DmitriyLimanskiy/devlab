# DevLab CLI

Первая локальная версия CLI: приветствие DevLab и настоящая интерактивная оболочка bash через PTY. Целевая платформа — macOS, Python 3.11+. Используется первый `bash` из `PATH`; для оперативного WebSocket используется websockets.

## Установка для разработки

В терминале:

```sh
cd /Users/dmitriysurov/Documents/projects/dev-lab/cli
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
devlab
```

После установки и активации окружения `devlab` можно запускать из любой папки. Перед запуском bash CLI предлагает папку проекта. По умолчанию предлагается папка, из которой запущен `devlab`: её путь указан в приглашении, Enter подтверждает выбор; можно ввести абсолютный или относительный путь, включая `~`. Недоступный путь запрашивается повторно. Ctrl+C / Ctrl+D отменяют запуск. Папка без Git разрешена: внутри bash можно выполнить `git init`.

Без установки пакета, из папки `cli/`:

```sh
PYTHONPATH=src python3 -m devlab
```

## Работа

Внутри сессии доступны обычные команды bash и установленные программы. DevLab не интерпретирует команды самостоятельно. Единственная подсказка управления сейчас — выход:

- `exit` — завершить bash и DevLab, вернуться в исходную оболочку.
- `Ctrl+D` на пустой строке — тот же выход.

`Ctrl+C` прерывает текущую команду. Размер окна передаётся вложенному терминалу. Код завершения bash становится кодом завершения DevLab. Доступны команды `devlab reset` и `devlab --help` (`-h`).

Оформление: компактный баннер, бирюзовый акцент и приглашение `devlab <каталог> >`. Для отключения цвета: `NO_COLOR=1 devlab`.

Bash запускается с временным rc-файлом: пользовательские `.bashrc` и login-профили не загружаются, история сессии не сохраняется в файл. Настройки пользователя на диске не меняются; переменные окружения и `PATH` наследуются. Это делает первый прототип предсказуемым; интеграцию пользовательских конфигураций нужно проработать отдельно.

## Проверка

```sh
python3 -m unittest discover -s tests -v
```

Тесты запускают реальный bash через вложенный PTY: команды, изменение размера, `Ctrl+C`, `exit`, `Ctrl+D`, код завершения и восстановление режима терминала. Для ручной проверки также запустите редактор, например `vi`, выйдите из него и из DevLab. Поддержка Linux и Windows пока не заявляется.

## Локальное наблюдение

После команд bash (в том числе неудачных) `PROMPT_COMMAND` передаёт код возврата по отдельному pipe. Вывод терминала не разбирается, команды и их вывод не архивируются. Отслеживается исходно выбранная папка, даже если внутри bash выполнить `cd`.

Наблюдатель опрашивает метаданные файлов каждые ~0,25 с, объединяет изменения с задержкой 0,3 с и сверяет Git не реже раза в 3 с. Это переносимый опрос, а не нативные уведомления ОС. Полный обход выбранной папки может быть дорогим для крупных проектов; короткие переходы состояния могут быть пропущены. Git читается дважды; при несовпадении или ошибке сохраняется предыдущий снимок и чтение повторяется позже. Это снижает риск смешанного состояния, но не гарантирует атомарный снимок при конкурентных операциях.

В начале сессии показывается путь `state.json` в выбранной папке. Его можно открыть из другого терминала: актуальное состояние содержит HEAD, ветку, локальные ветки и теги, статусы индекса/рабочих файлов, конфликты, незавершённые операции и до 200 коммитов с родителями. Метаданные авторов и сообщения коммитов пока не включаются. Номер версии и время меняются только при изменении состояния. `state.json` сохраняется после выхода и атомарно обновляется при изменении состояния. Если файл уже есть, CLI спрашивает `yes/no`: `yes` обновляет снимок сразу, `no` сохраняет файл при запуске и обновляет его только после следующего изменения Git относительно начала сессии. При `no` номер версии продолжается из существующего файла, если он корректен. Ссылки и каталоги `state.json` не перезаписываются. Сам снимок исключён из списка файлов снимка и из наблюдения за метаданными, чтобы не вызывать обновления самого себя. Перед запуском bash CLI создаёт `.gitignore` в выбранной папке или дополняет существующий правилом `state.json`, сохраняя его содержимое. Повторный запуск не дублирует действующее явное правило. Символическая ссылка вместо `.gitignore` не изменяется: запуск останавливается с сообщением. Уже отслеживаемый Git файл это правило не исключает из индекса автоматически. Код последней команды хранится отдельно во временном служебном каталоге и удаляется после выхода. Содержимое рабочих файлов и diff не сохраняются.

## Границы версии

Это локальная основа Git-песочницы. Подключение, фоновая отправка изменившихся состояний и повторная доставка реализованы. Получение снимков браузером и WebSocket пока отсутствуют. Поддержка подмодулей, дополнительных рабочих деревьев и Git LFS отдельно не проверена.

## Подключение к курсу

Перед запуском CLI откройте Git-песочницу в браузере, чтобы создать активную сессию. При запуске `devlab`:

1. CLI получает `GET /api/v1/catalog`, показывает курсы по `position` и пункт `0` для локальной работы.
2. После выбора отправляет `POST /api/v1/cli/connect` с `{"course_slug":"git"}`.
3. Получает `session_id`, новое `generation` и ключ. Ключ хранится только в памяти процесса, не выводится и не передаётся в окружение bash или state.json.
4. Затем предлагает выбрать папку и обработать существующий state.json.
5. После запуска bash наблюдатель читает актуальное состояние и ставит начальный снимок в фоновую очередь: schema_version=1, version=1, session_id, generation и state. Ключ находится в Authorization: Bearer.
6. Отдельный отправитель проверяет подтверждённые session_id/generation/version; работа bash не ждёт сети.

Начальный снимок формируется заново, а не читается из старого state.json, в том числе при ответе no. Локальная версия файла не используется как сетевая версия нового поколения.

По умолчанию сервер — `http://127.0.0.1:8080`. Другой адрес (без `/api/v1`):

```sh
DEVLAB_SERVER_URL=https://devlab.example.com devlab
```

Для явного запуска без сетевых запросов:

```sh
DEVLAB_OFFLINE=1 devlab
```

Значения задаются окружением текущего процесса, `.env` автоматически не читается. Для удалённого сервера используйте HTTPS. Таймаут HTTP-запросов — 3 секунды, автоматические перенаправления отключены. Подключение не повторяется автоматически, чтобы без необходимости не менять поколение.

Если сервера нет, можно повторить запрос (`r`) или продолжить локально. Если нет активной сессии, CLI предлагает открыть выбранный курс в браузере; затем можно выбрать курс повторно или перейти в локальный режим. Пустой каталог тоже допускает локальную работу. Ctrl+C/Ctrl+D в диалогах отменяют запуск.

Начальный и последующие снимки отправляются в фоне. После команд, включая неуспешные, и правок IDE перечитывается Git. Опрос обновляет локальный state.json. Сетевой снимок ставится в очередь только при начальном чтении, после завершения команды или при выходе, если состояние отличается от последнего поставленного в очередь. Правки IDE между командами объединяются в следующий сетевой снимок. Команда без изменения состояния отправку не вызывает. Поток отправителя запускается после PTY fork, отдельно от наблюдения и оболочки.

В FIFO-очереди хранятся все наблюдавшиеся изменившиеся состояния. Пока один запрос выполняется, может появиться новый снимок. Подтверждение старого запроса не удаляет новый. Версия при повторе не увеличивается. Локальная версия state.json и сетевая версия независимы; каждое новое поколение начинает сеть с 1.

При временной ошибке сети, HTTP 408/429 или 5xx запрос повторяется с задержкой 1, 2, 4… до 30 секунд. Новые снимки ожидают подтверждения предыдущих и отправляются по порядку. Отсутствующее/неверное подтверждение тоже не считается доставкой. При постоянных ошибках 4xx (например, 401, 404 или 409) отправка останавливается, последний снимок сохраняется, bash продолжает работать. Новое подключение автоматически не создаётся.

Список неподтверждённых тел запросов атомарно сохраняется в `~/Library/Application Support/DevLab/pending/`, отдельным файлом для сервера, сессии, папки и поколения. Ключа в нём нет; файл создаётся с правами 0600. Для другого места задайте `DEVLAB_STATE_DIR`. Служебная папка исключена из чтения статусов файлов и опроса даже при размещении внутри выбранного проекта. Не используйте корень проекта как DEVLAB_STATE_DIR: выбирайте отдельную служебную папку.

После подтверждения снимок удаляется из головы очереди; файл удаляется после подтверждения всей очереди. При выходе CLI ограниченно ждёт отправку очереди (до таймаута запроса плюс небольшой запас), затем завершает работу и сообщает о неподтверждённом состоянии. Бесконечные повторы не задерживают выход. Если запись очереди на диск не удалась, это явно указывается: состояние остаётся только в памяти.

В том же процессе после восстановления сети последовательно отправляются все ожидающие состояния с прежними ключом и поколением. После перезапуска нужен новый cli/connect, так как ключ хранится только в памяти. Новый наблюдатель заново читает Git, начинает сетевую версию с 1 и сохраняет файлы очередей предыдущих поколений для той же сессии/папки. При выходе сообщает об оставшихся старых очередях. Старые снимки не воспроизводятся с новым ключом. Без подключения (локальный режим) прежняя очередь не отправляется.

Backend сохраняет историю снимков; frontend получает последний снимок, страницы истории и уведомления WebSocket. ID строки назначает сервер, CLI его не отправляет.

HTTP-тесты поднимают локальный сервер; им нужен доступ к loopback-портам. Проверяются выбор курса перед папкой в PTY, отсутствие ключа в выводе/файлах, начальная отправка, неверное подтверждение, ошибка доставки, отсутствие сессии и сервера. Локальные терминальные тесты явно используют DEVLAB_OFFLINE=1.


## Присутствие в браузере

После запуска bash отдельный поток подтверждает присутствие CLI каждые 10 секунд через `/api/v1/cli/heartbeat`. Это не создаёт снимков и не повышает версии. При нормальном выходе отправляется `/api/v1/cli/disconnect`; если сеть недоступна или процесс аварийно завершился, статус погаснет после 35 секунд без подтверждения. Ошибки сети не блокируют bash; недействующий ключ останавливает heartbeat без автоматического переподключения. Ключ остаётся в памяти. При выходе сетевое ожидание ограничено.

Приглашения bash и этапы запуска разделяются пустой строкой. Собственные сообщения DevLab выводятся без завершающей точки; вывод Git и остальных программ не изменяется.

## Данные графа в state.json

CLI читает историю локальных веток, тегов, указывающих на коммиты, и HEAD независимо от наличия коммита в текущей ветке. Коммиты идут в топологическом порядке: потомки перед родителями, порядок родителей merge-коммита сохраняется. Данные не зависят от ранее открытой вкладки браузера. Недостижимые коммиты из reflog и история команд в снимок не входят.

- `refs` сохраняет исходные SHA объектов локальных веток и тегов
- `ref_commits` сопоставляет полные имена refs с SHA коммитов, раскрывая в том числе вложенные annotated tags; теги на деревья и blobs отсутствуют в этой карте
- `commits` содержит до 200 коммитов с полными SHA и упорядоченными `parents`
- `history_truncated` показывает, что достижимая история превышает лимит 200
- `history_boundary` перечисляет SHA родителей за пределами переданного списка
- `is_shallow` отмечает shallow-репозиторий: Git может скрывать родителей на границе клонирования даже без превышения лимита

Снимок сохраняет структуру обычных слияний после удаления указателя ветки, если коммиты остаются достижимыми и входят в лимит. Название удалённой ветки восстановить из коммитов нельзя. Frontend восстанавливает линии по серверной истории снимков без локального хранилища и отображает признаки неполной истории.

Новые поля принимает модель backend с совместимыми значениями по умолчанию для прежних снимков. Миграция БД не требуется: состояние хранится в JSONB. Backend с обновлённой моделью необходимо развернуть до отправки снимков обновлённым CLI.

## Оперативная доставка файлов

Отдельный поток worktree.py отправляет только kind/path/files по постоянному WebSocket /ws/cli-worktree, независимо от очереди графа и ошибок её сохранения. После начального чтения поток проверяет state.json каждые 0,3 секунды и формирует пакет при изменении статусов; без изменений повторная версия не создаётся. При потере сети достаточно последнего состояния; очередь не сохраняется на диск. Последний пакет повторяется каждые 10 секунд с прежней версией для восстановления памяти backend после перезапуска. Ошибки ключа/поколения останавливают этот отправитель без автоматического cli/connect.

Исторические снимки для БД содержат files=[]; редактирование или git add без изменений других полей не добавляет запрос в очередь графа. Локальный state.json по-прежнему содержит полные статусы файлов. Для перехода с прежней версии нужно перезапустить CLI.

Наблюдатель обновляет локальный файл при внешних изменениях независимо от команд. Периодический отправитель читает только JSON текущего запуска, игнорирует старый или временно недоступный файл и восстанавливает WebSocket с прежним ключом/поколением. В режиме no начальное состояние берётся из свежего чтения Git. После изменения зависимостей переустановите CLI командой `python -m pip install -e .`; в текущем cli/.venv зависимость установлена

## Структура пакета

`src/devlab/main.py` запускает приложение, `cli/` содержит подключение и heartbeat, `practice/` — чтение Git, наблюдение и отправителей состояния, `shell/` — интерактивный bash через PTY. Команда запуска остаётся `devlab`


При успешном подключении CLI выводит только название курса, без UUID сессии и поколения. Путь к локальному снимку и служебные сообщения о сохранении прежнего файла и фоновой синхронизации не выводятся. После завершения оболочки выводятся «Сессия DevLab завершена» и «Хорошего дня».


## Сброс истории и справка

`devlab --help` показывает команды и способ выхода из bash без подключения к серверу и без требования интерактивного терминала. Переменные окружения и служебные пояснения сброса в справке не выводятся.

Внутри открытой bash-сессии `devlab reset` обращается к основному процессу CLI через приватный Unix-сокет. Основной процесс останавливает снимки, файлы и heartbeat, дожидается текущих запросов и отправляет DELETE с прежним ключом, поколением и reset_id. Backend сохраняет ключ и увеличивает generation. После подтверждения CLI удаляет очередь остановленного поколения, читает свежий Git и запускает отправителей с версии 1. Папка, процесс bash и локальная история Git сохраняются. Браузер автоматически перечитывает историю; текущий граф снова появляется как начальное состояние.

Ключ не передаётся дочерней команде: окружение bash содержит только путь DEVLAB_CONTROL_SOCKET. Сокет создаётся в приватном временном каталоге и удаляется при выходе. Если ответ reset потерян, bash продолжает локальную работу, а отправители остаются приостановленными. Повторите `devlab reset`: основной процесс завершит тот же сброс с прежним reset_id без второго увеличения поколения. Очереди других поколений автоматически не удаляются.

Вне открытого CLI `devlab reset` по-прежнему предлагает выбрать курс и создаёт отдельное подключение, отзывающее прежний ключ. Для сохранения текущего CLI запускайте reset внутри его bash. В DEVLAB_OFFLINE=1 сброс недоступен. Ошибки возвращают код 1, неизвестные аргументы — код 2.
